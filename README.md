# 充电桩电气原理图自动设计平台

填写充电标准、功率、枪数与储能配置，由**确定性算法**选定器件档位并自动生成 A3 充电桩电气原理图（SVG / DXF / JSON 方案包）。同一份输入永远得到逐字节相同的输出。

> **边界声明**：本项目输出为 `CONCEPT_DRAFT—PROFESSIONAL_REVIEW_REQUIRED`，是方案级自动原理图，**不是**生产图、施工图、设备报价、保护整定书、型式试验结论或任何标准符合性证明。适用标准、现场资料、短路计算、认证与签发必须由具备相应资格的人员完成。

```
npm start          # 本地起服务，浏览器打开 http://localhost:3000
npm test           # 6 组回归：引擎 / 几何 / 布线 / 图↔网表 / 规则包 / 图面体检
npm run test:matrix   # 216 组参数矩阵扫描，通过率必须 100%
npm run check      # 语法自检
```

## 一、分层架构

1.0.13 最大的结构问题是：工程模型每次都产出完整网表（45 设备 / 111 端口 / 84 回路），而渲染器对 `R.design` 的引用次数是 **0** —— 渲染器绕开模型，用手写坐标把同一份拓扑重画一遍。校验器（全局几何自检）因此比生成器（手摆坐标）更强，216 组参数里有 18 组被闸门阻断，且全部集中在「国标 4 枪」这一最常见的商用配置。

1.1.0 把这条链拆成六层，每层职责单一、可单独测试：

| 层 | 文件 | 职责 | 不做什么 |
|---|---|---|---|
| ① 选型 | `engine/engine.js` `ev-standards.js` `component-library.js` `connector-library.js` | 参数 → 器件档位（模块台数、进线电流、开关/电缆、直流保护、枪回路、电池簇与变换器） | 不知道任何坐标 |
| ② 模型 | `engine/design-model.js` | 选型结果 → EDEM 工程网表：设备 + 具名端口 + 回路（netClass） | 不知道任何坐标 |
| ③ 布局 | `engine/placement.js` | 坐标即数据：分区、基准线、串联链路、设备 bbox、端口锚点、走线通道、障碍矩形 | 不画一根线 |
| ④ 布线 | `engine/router.js` | 通道 + 轨道模型，区间图着色分轨，障碍避让 | 不知道线是什么颜色 |
| ⑤ 渲染 | `engine/draw-pile.js` `symbols.js` `color-scheme.js` | 消费 ①②③④ 输出 SVG；交叉半圆统一后处理 | 不再手摆坐标（字面量已从 60+ 降到 7） |
| ⑥ 闸门 | `engine/drawing-skill.js` | 阻断式规则包：图纸不合格就**不许导出** | 不修图 |

`engine/` 是唯一真源，根目录 `js/` 是浏览器侧副本，用 `npm run sync:web` 同步（CI 会校验两者一致）。前端就在站点根目录（`index.html` + `js/`），任何静态托管直接开域名即可，不存在子路径相对路径问题。

## 二、闸门做了什么

图纸生成后必须过闸门才允许导出，任何一条 ERROR 直接阻断：

- **语义规则**（从 `sch_lib/` 两张参考图提炼）：每枪独立快熔与正负极接触器、枪 PE、直流绝缘监测、交流进线保护、储能预充与并入方式、辅助电源来源。
- **几何自检**：未跨越的正交交叉、共线重叠、走线穿设备、平行信号线间距 ≥6px。
- **图↔网表一致性**（1.1.0 新增，此前完全缺失）：
  - `G050-NET-COVERAGE` 网表里的回路必须画出，或在规则包 `UNDRAWN_CIRCUITS` 中登记并写明理由；
  - `G051-NET-ORPHAN` 图上每根走线必须能归属到回路，且不得出现网表里没有的回路；
  - `G052-NET-CONTINUITY` 同一根导线的线段必须首尾相连，不得出现断开的孤立段。

已知缺口清单放在**规则包**而不是渲染器里 —— 渲染器不能自己给自己发合格证。

### 交叉半圆：从碰运气到构造性保证

1.0.13 用三处「边画边查局部注册表」的手工跳线逻辑，两套互不知情的注册表正是国标 4 枪被阻断的成因。1.1.0 改为统一后处理 `SYM.resolveCrossings`，**复用闸门自身的检测口径**：生产端满足校验端从此是构造性的，且与绘制顺序无关（正序/逆序半圆数一致）。L 形走线不再输出 `<polyline>`（闸门几何自检只解析 `<line>`，polyline 是盲区）；走线带 `data-w` 标记，后处理只打断走线，不打断设备符号内部线。

## 三、支持的充电标准

| 标准 | 接口 | 通信 | 进线 |
|---|---|---|---|
| 国标 GB/T | GB/T 20234.3（9 芯 DC±/PE/S±/CC1/CC2/A±） | GB/T 27930 CAN 250kbps | AC 380V 3P+N+PE |
| 欧标 CCS2 | IEC 62196-3 Configuration FF（DC±/PE/CP/PP） | DIN 70121 / ISO 15118（HomePlug Green PHY） | AC 400V 3P+N+PE |
| 美标 CCS1 | IEC 62196-3 Configuration EE（DC±/PE/CP/PP） | DIN 70121 / ISO 15118 / SAE J2847-2 | AC 480V 3P+PE（Delta，无中性线） |

连接器库另含 NACS（SAE J3400）与 CHAdeMO 触点定义。

## 四、图面分区

① 交流进线与保护 · ② 功率变换（AC/DC 模块阵列） · ③ 直流保护与计量（总快熔 / 霍尔 / 直流计量 / IMD / 泄放） · ④ 充电枪回路（每枪独立快熔 + 正负极接触器 + 电子锁 + PE + 导引通信） · ⑤ 储能（电池簇 / 熔断 / 主接触器 / 预充 / 双向 DC-DC 或 PCS / BAMS） · ⑥ 二次控制与通信（CCU / SECC / 路由 / HMI / 急停 / 门禁） · ⑦ 辅助电源与热管理，外加线型图例与设备明细表（全部条目标 `RFQ_REQUIRED`）。

## 五、选型的确定性

档位取自标称序列（断路器 / 接触器 / 快熔 / 电缆 / 开关电源 / PCS / DC-DC）。**当计算值超出内置序列上限时，引擎显式抛出告警，绝不静默取最大档** —— 这是 1.0.x 的一个真实缺陷（1000A 需求被悄悄压到序列末档）。交流进线电流计算包含辅助负荷与热管理负荷。
